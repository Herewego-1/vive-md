# 바이브코딩 워크플로우 오케스트레이터

## 개요

superpowers 워크플로우와 vive-md 방법론을 통합한 바이브코딩 전체 프로세스.
에이전트는 코드 작성 전 반드시 이 워크플로우를 따른다.

```
브레인스토밍 → 설계 승인 → 계획 작성 → TDD 구현 → 코드 리뷰 → 검증 → 완료
```

---

## 핵심 원칙 (Iron Laws)

<HARD-GATE>
1. 설계 승인 없이 코드 작성 금지
2. 테스트 없이 구현 코드 작성 금지
3. 검증 없이 "완료" 선언 금지
4. 증상이 아닌 근본 원인 파악 후 버그 수정
</HARD-GATE>

---

## 워크플로우 단계

### Phase 1: 브레인스토밍 (설계 탐색)

**목적**: 구현 방향을 결정하기 전에 가능한 접근법을 탐색한다.

1. 요구사항 파악: "무엇을", "왜", "어떤 제약 조건"
2. 2-3가지 접근 방식 제안 (각각 트레이드오프 포함)
3. 기존 코드/패턴 재사용 가능성 확인
4. **사용자 승인 대기** — 승인 전 다음 단계로 진행 금지

### Phase 2: 계획 작성

**목적**: 구현을 2-5분 단위의 bite-sized 태스크로 분해한다.

계획에 포함할 내용:
- 정확한 파일 경로
- 각 태스크의 완성 기준
- 테스트 케이스 목록
- 순서와 의존성

### Phase 3: TDD 구현

**RED → GREEN → REFACTOR 사이클:**

```
1. 실패하는 테스트 작성 → 실제로 실패하는지 확인
2. 최소한의 코드로 테스트 통과
3. 리팩토링 (테스트는 계속 통과해야 함)
```

각 태스크 완료 후 체크:
- [ ] 테스트가 GREEN인가?
- [ ] 기존 테스트가 깨지지 않았는가?
- [ ] 코드가 단순한가? (과도한 추상화 없는가?)

### Phase 4: 코드 리뷰

리뷰 체크리스트:
- [ ] 계획과 구현이 일치하는가?
- [ ] 보안 취약점 없는가? (OWASP Top 10)
- [ ] 불필요한 코드/의존성 없는가?
- [ ] 에러 처리가 적절한가?

### Phase 5: 검증 & 완료

<HARD-GATE>
완료 선언 전 반드시 실행:
1. 전체 테스트 스위트 실행 → 결과 캡처
2. 빌드 성공 확인
3. 주요 기능 수동 검증
4. 검증 증거를 사용자에게 제시
</HARD-GATE>

## 기술 스택별 빠른 참조

| 스택 | 테스트 도구 | 빌드 명령 |
|------|------------|----------|
| React 18+ | Jest + RTL | `npm run build` |
| Vue 3 | Vitest | `npm run build` |
| Next.js 14+ | Jest + Playwright | `npm run build` |
| Spring Boot | JUnit 5 + Mockito | `./gradlew build` |
| Python FastAPI | pytest | `uvicorn main:app` |

## 안티패턴 (하지 말 것)

| 변명 | 현실 |
|------|------|
| "간단한 거라 테스트 필요 없어" | 단순한 변경이 복잡한 버그를 만든다 |
| "나중에 리팩토링할게" | 나중은 오지 않는다 |
| "아마 동작할 거야" | 검증하지 않으면 모른다 |
| "설계는 코드 짜면서 생각해" | 설계 없는 코드는 기술 부채다 |

## 방법론 선택 가이드

- **신규 개발**: Waterfall (기획 → 요구분석 → 설계 → 구현 → 테스트 → 배포)
- **운영/유지보수**: Kanban (SLA 기반, 인시던트 대응, 흐름 최적화)
- **빠른 프로토타입**: 바이브코딩 (설계 승인 후 빠른 반복)
